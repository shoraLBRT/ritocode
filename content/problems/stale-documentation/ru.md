## Signs

- В README команда запуска `python main.py --input`, а у программы нет такого параметра.
- Docstring обещает `Returns: list of orders`, а функция возвращает словарь.
- Описание API перечисляет поля, которых в ответе нет, и не знает о новых.
- README описывает возможности, которые в коде не реализованы.

## Why AI does it

Агент пишет документацию по задаче, а не по готовому коду, или обновляет код и не возвращается к
описанию. Красивый README выглядит как законченная работа, и никто не сверяет его с кодом.

## Cost

- Новый человек следует инструкции, и она не работает, — он теряет время и доверие к документации.
- Клиенты API пишут код по описанию и ломаются на настоящем ответе.
- Документация обещает возможности, которых нет, и решения принимаются по ней.
- Следующий запуск агента читает документацию как правду и пишет код под неё.

## Acceptable when

Почти никогда. Документация, о которой известно, что она устарела, лучше помечена или удалена, чем
оставлена как есть.

## Detection

Примеры из документации, которые запускаются как тесты; описание API, которое генерируется из кода
или проверяется против него в CI.

## Treatment

Привести документацию в соответствие с кодом и сделать её проверяемой — запускаемые примеры,
описание API из кода; в правилах репозитория — обновлять документацию в том же изменении.
Неправильное лечение — дописать в README абзац «некоторые сведения могут быть устаревшими».

## Counter-arguments

Многие считают, что код и есть лучшая документация, а отдельные описания всегда устаревают. Это
довод за то, чтобы документации было меньше и чтобы она проверялась, а не за неверную.
