## Signs

- `eval(request.args["expr"])`, чтобы посчитать формулу из запроса.
- `os.system(f"convert {filename} out.pdf")` или `subprocess.run(cmd, shell=True)` с именем файла
  от пользователя.
- `pickle.loads` для данных из запроса, куки, очереди или загруженного файла.
- `yaml.load(text)` без `SafeLoader` для файла, который присылает пользователь.

## Why AI does it

`eval` и `shell=True` решают задачу в одну строку: посчитать выражение, вызвать утилиту, сохранить
объект. Что строка может прийти от злоумышленника, в задании не сказано.

## Cost

- Злоумышленник выполняет на сервере любой код: читает базу и секреты, ставит свои программы.
- Одной такой строки достаточно, чтобы потерять сервер целиком.
- Такие места трудно заметить на ревью, если данные попадают в них через несколько функций.

## Acceptable when

Никогда для данных извне. Внутренний инструмент, который исполняет только код своего автора, —
единственное исключение, и оно должно быть очевидным из кода.

## Detection

Статический анализатор безопасности находит `eval`, `exec`, `pickle`, `shell=True` и небезопасную
загрузку YAML; запрет этих вызовов линтером.

## Treatment

Не исполнять чужие данные: разбирать формулы своим разборщиком, вызывать программы списком
аргументов без оболочки, хранить данные в JSON; записать запрет в правила и включить анализатор.
Неправильное лечение — фильтровать «опасные» символы перед `eval` или `shell=True`.

## Counter-arguments

Нет. Для задач вроде вычисления формул есть безопасные способы — `ast.literal_eval`, свой
разборщик, — и спорят только о том, какой из них удобнее.
